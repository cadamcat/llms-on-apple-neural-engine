# Qwen3-4B: an ANE graph sized to each input

A complete Qwen3-4B FP16 model, measured through Core AI on ANE and GPU on one M5 Pro, with an ANE graph whose capacity matches each input: <!-- claim:g4a.capacities@g4a-001 -->768 / 1,280 / 2,304 / 4,352 / 8,448 / 16,640<!-- /claim --> positions for <!-- claim:g4a.contexts@g4a-002 -->500 / 1,024 / 2,048 / 4,096 / 8,192 / 16,384<!-- /claim --> input tokens. The GPU uses its <!-- claim:g4a.gpu-capacity@g4a-003 -->32,768<!-- /claim -->-position asset. The GPU is faster at every input. ANE uses less component energy for short prefill, and decode energy per token is close. Against the earlier [256 / 2K / 32K graph ladder](../qwen3-4b-prefill-decode/), the matched graphs remove most of ANE's long-input slowdown.

## Boundaries

- **Decode is teacher-forced.** At a given input size, both paths process the same continuation of 257 token IDs for the same number of steps. Across sizes, attention work grows with KV length; this is not a generation-quality measurement. Each arm's warmup kept finite first and last logits, and the 1K arms matched an independent reference within the recorded thresholds.
- **ANE execution** is supported by ANE counter energy in every ANE block and by short per-tier checks that logged direct ANE requests from the host process. It does not establish exclusive per-operation placement. The system GPU counter also records energy during these windows, without attribution to a process or operation. [SCOPE](../../docs/SCOPE.md#g4-a-matched-graph-observations)
- **Two runs.** Three decode requests per arm share one host session; they are repetitions, not independent processes. G6 reran every arm in a new host session ([below](#repeat-and-decode-query-width)). Energy blocks are admitted one by one: complete power stream, block end at least <!-- claim:g4a.margin@g4a-174 -->15 s<!-- /claim --> before the last power sample, a power response to the work and timing coverage at 0, 1, 2 and 5 s lags.
- **Disk.** Each ANE host left a large compile input held by a system service during the run; see [its finding](../ane-compiler-service-disk/). The wait it caused fell between blocks.
